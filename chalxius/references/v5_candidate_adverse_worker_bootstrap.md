# V5 exact Candidate-adverse bootstrap

This is the complete compact startup contract for one current whole-Candidate
adverse worker. It attacks one exact Main-selected canonical Candidate Fact
after every applicable Research supervision result is complete and before
Candidate packaging; the applicable set may be empty when no supervision scope
applies. The canonical bytes may be Main-authored; authorship and provenance
metadata are lineage rather than mathematical validity. The worker creates
nontruth Research only.

## Applicability

Use this path only when the immutable task card has all of these literal facts:

- `work_mode="refute"`;
- no `research_cycle` field;
- current `assurance_contract`;
- `mathematical_state.source_research_dossier.metadata.independent_adverse_required=true`;
- exactly one authorized `candidate_fact` byte object after path/hash
  deduplication;
- exact-card worker CHX startup accepts the task-card semantic hash and owner
  boundary.

`runtime_binding`, when present, is diagnostic provenance only and cannot make
the current runtime or a historical archive a prerequisite for this refute
operation.

The assignment and card prove only that Main planned this adverse work. They
are not dispatch evidence. Main must launch this worker through the host and
confirm the actual start before using this bootstrap; that confirmation creates
no new graph receipt or mathematical gate.

Any missing, ambiguous, legacy, or inconsistent selector fails closed to the
ordinary route in `SKILL.md`. This assignment is not Research production and
must not load `v5_production_worker_bootstrap.md`.

Read completely, in order:

1. the candidate's full `SKILL.md`;
2. the generated prompt and exact task card;
3. this reference;
4. the one Main-selected canonical Candidate Fact, every applicable frozen
   Research-supervision report authorized by the card (possibly none), and any
   other exact artifact explicitly authorized by the card.

Read each unique path/hash byte object once. Do not preload the unified
architecture, release, admission, Paper, computation, Blackboard, Learner,
Campaign, PHX, or broad agent protocols.

## Review boundary

Independently attack the complete Candidate statement under its literal
hypotheses. Test conclusion atomicity and claim strength; implication direction;
quantifier scope; types; boundary cases; hidden premises; circularity;
predecessor use; and whether every applicable frozen supervision repair reaches
the exact Candidate bytes. Verify that every advertised scope exclusion occurs in the
statement rather than only in surrounding prose.

Do not re-run constructive production, silently weaken or rewrite the Fact,
search generically for objections to admitted Fact premises, package a
Candidate, invoke a verifier, create a Certification Decision, or admit a Fact.
If a required source or computation byte is absent from the card, report the
exact capability boundary instead of fetching or inferring it.

Do not infer correctness or scope from who authored the Candidate Fact or from
actor/provenance metadata. Attack the exact authorized bytes and their literal
interfaces. The later fresh verifier returns review bytes; Gateway alone owns
`certification-record` and Fact admission.

Workers report concrete failures and boundaries. They never write a persistent
attack-route rule or philosophical abstraction. Main alone may compare reports
and synthesize a bounded mechanism-level future rule. Keep
`attack_learning=null` for a clean result, concern, or non-load-bearing
suggestion. Before returning a surviving counterexample or a productive
challenge with non-null `attack_learning`, read
`adverse_routing_evolution.md` and use its exact failure-report schema.

## Exact return

Write one schema-5 return to the exact card path with these fields:

- `schema_version`, `project_id`, `round_id`, `assignment_id`, `worker_id`;
- `task_card_sha256`, `blackboard_snapshot_sha256`;
- `outcome`, `claim`, `content`;
- `narrative` with exactly `rationale`, `summary`, `intuition`, `limitations`;
- `artifacts`, normally `[]` unless a card obligation requires one;
- `obligation_dispositions`, exactly covering the card obligations;
- `computation_manifest`, normally `null`;
- `research_assurance` with exactly `source_uses`, `route_invalidations`,
  `extremal_cases`, `claim_strength`, `contour_substitutions`,
  `claimed_structures`, and `program_math_alignments`;
- `attack_learning`, normally `null`.

The output is nontruth Research. A clean review is evidence for later Main
disposition; it is not a Candidate Release, verifier verdict, Certification,
Gateway acceptance, or Fact.

## CHX and completion

Before substantive review, start the candidate's `chx_ledger.py` with the
exact project root, host scope, and task-card path. Runtime, manifest, card, or
canonical-root mismatch must fail before ledger creation. If architecture
causes or materially amplifies a problem, read `chx_runtime_ledger.md` and
record the concrete mechanism. A mathematical defect is not a CHX finding.

After completing the draft: run strict `preflight-return`; require the canonical
target to be absent; copy the passing bytes exactly; compare them byte-for-byte;
run canonical `validate-return`; close CHX; and hand off only `assignment_id`
and status. A legacy return SHA-256 is optional and is only an equality
assertion. `validate-return` observes one bounded
return/artifact snapshot. A transient `ENOENT` or `ESTALE` before a safe
snapshot is visible may be retried after the same paths stabilize and creates
no quarantine. An unsafe filesystem object or visible malformed,
hash-drifted, schema-invalid, or semantically invalid bytes remain fail-closed
and use the ordinary local-quarantine path. Do not create a clean-review
artifact unless the task card requires one, and do not repeat status-only
last-mile milestones.

Main, not a worker-side service, observes these visible milestones and may
reclaim or redirect stalled work. This is an ordinary host instruction only:
there is no timer, daemon, watcher, heartbeat, numeric threshold, persisted
performance state, or additional review/admission gate.
