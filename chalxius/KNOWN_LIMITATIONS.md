# Known architecture limitations in Chalxius 0.5.0

Chalxius 0.5.0 is being released by an explicit user decision before every
architecture issue observed in a private field run has been resolved. Software,
manifest, archive, and installation checks do **not** close any issue below.
This file is a public, content-free summary; the project-specific ledger and its
research material are intentionally excluded from the package.

The release is prospective. It does not migrate or rewrite a project, reopen a
frozen task card, change an admitted Fact, or require old work to be repeated.
CHX issues remain nontruth architecture records and must not be converted into
adverse-routing rules.

## Release posture

- The initial `source_role` contract distinguishes `research_draft` from
  `external_reference`, preserves older objects as `legacy_unspecified`, and
  keeps source role orthogonal to Evidence/Fact authority. This is a partial
  compatibility mechanism, not resolution of CHX-001 or CHX-002.
- Paper Evidence remains background, inspiration, research material, and a
  citation source. It is never premise-eligible merely because it is archived.
- Until the relevant issues are closed, load-bearing paper workflows should
  preserve the complete atomic DAG, exact source units, typed cross-plane
  mappings, transported snapshot closure, and claim-complete verifier scope.
  If those bindings are unavailable, keep the result in Research rather than
  weakening Candidate Release, fresh-verifier, or Fact Gateway requirements.

## Open field issues at the release freeze

1. **CHX-001** — Research-draft authority-plane misrouting and whole-paper admission loss.
2. **CHX-002** — Domain-general research-draft lifecycle and source-role contract missing.
3. **CHX-003** — Research-draft cross-plane admission preflight missing.
4. **CHX-004** — Single-Fact Paper coverage row conflicts with semantic atomization.
5. **CHX-005** — Target-local failure-surface ids can validate the wrong semantic surface.
6. **CHX-006** — Weaker Paper paraphrase can shadow stronger source claims while full-graph review still passes.
7. **CHX-007** — Argumentative source-unit presence can masquerade as semantic-total Paper coverage.
8. **CHX-008** — Version-specific generated witness text can invalidate an otherwise current semantic reconstruction.
9. **CHX-009** — Nearby source text can be misassigned across speaker and proposition boundaries.
10. **CHX-010** — Single-target continuation disposition repeatedly revalidates immutable whole-plan state.
11. **CHX-011** — Cross-target technical-term conflicts are admitted by continuation adequacy and detected only at Candidate Release.
12. **CHX-012** — CHX-010 repeated-validation pressure extends from disposition into the sealed release and read-only lifecycle.
13. **CHX-013** — Newly discovered CHX mechanisms can remain unpromoted because issue recording, relationship lineage, and report synchronization are not one enforced transaction.
14. **CHX-014** — Monolithic fresh-verifier contract lacks context-bounded sharding, seam coverage, conflict adjudication, and mechanically composable review receipts.
15. **CHX-015** — Paper EvidenceRef validation is project-relative while a sealed release and verifier capsule need not transport the referenced snapshot closure.
16. **CHX-016** — Domain- and language-incomplete interface projection can erase conditional, temporal, comparative, applicability, quantifier, and typed-object structure.
17. **CHX-017** — Declared one-conjunct cardinality can masquerade as semantic atomicity.

This registry is frozen to the field-ledger state used for the 0.5.0 release.
Later ledgers may add, refine, or close issues; absence from this file is not a
claim that no other architecture limitation exists.
