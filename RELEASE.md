# Chalxius v0.9.12 — Frontier Lifecycle Closure

Chalxius 0.9.12 repairs the remaining cases in which a correct research
lifecycle existed in immutable graph bytes but Main's ordinary frontier did
not present it as the current working boundary. It also removes one repeated
read from the bounded frontier path and distinguishes an intermediate host-tool
yield from a completed command with missing output.

The release adds no automatic mathematical selector, dispatcher, daemon,
persistent index, compatibility layer, migration ceremony, workflow gate,
Candidate effect, or Fact effect.

## Frontier lifecycle closure

An exact historical copy-on-write chain can now reach its terminal Research
even when its Main-authored repair root predates the dedicated `kind=repair`
shape. The projection accepts only a complete, unique relation/source/product/
challenge/Campaign/dependency/chronology match. Ambiguous graph shapes remain
pending, and no frozen Research is rewritten.

For multi-head Campaign goals, a real `await_return` branch is now the
foreground `in_flight` state. Older branches that need reconciliation remain
present in `active_head_actions`; the runtime neither deletes them nor decides
their mathematical relevance.

One frontier command reuses Research envelope bytes it has already read and
hash-validated, then runs the complete record and artifact validator on that
parsed object. The reuse is command-local and leaves no cache file or long-lived
state.

Main's runtime instructions now treat a host process with a live session and
no final exit or JSON as still running. Main resumes that session rather than
duplicating a mutating planner. A completed command with invalid required
output still remains an explicit defect.

## Included continuity work

This public release also carries the 0.9.11 frontier and source-continuity work
developed after v0.9.10: routine frontier rows retain concise current, recent,
and historical mathematics while deep topology stays diagnostic; completed
terminal descendants can serve Campaign handoff; recognized private atomic
staging does not abort round inventory; and source-scope supervision can follow
exact completed source-review provenance without duplicate byte returns.
